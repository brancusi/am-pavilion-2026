# Armenian Pavilion 2026 site — working notes

The map of the repo is in `README.md`; recent history in `CHANGELOG.md`. This file is how we work.

## Ground rules

- **Zero layout shift.** Every page stays at CLS 0.0000 at 1440 and 390 wide. Give every image, film
  and late-loading block its footprint (aspect ratio, fixed height, or a Suspense `:fallback` of the same
  size). Check with `npm run qa:cls -- http://localhost:4200 [paths…]` before shipping, and
  `npm run qa:cls -- https://armenianpavilion.org | grep -v 0.0000` (prints nothing) after.
- **Lazy by default.** Pages are shadow-cljs modules loaded with `lazy-component`; heavy code (Mapbox,
  Three.js, Mux Player, the living grounds) loads only when it is about to be on screen
  (IntersectionObserver), and anything animated stops while off screen and under reduced motion.
- **Media is immutable.** R2 images (`npm run media`) are cached for a year: replace by uploading under a
  new key. Films are Mux public playback ids; never change or delete an asset's playback settings.
- **Ship with the `push-to-production` skill**, after each round of fixes, not only at the end.
  Never stage dev output under `public/` (js, css, data, images, fonts, financial-reports); commit
  `release/` on its own as "Release build <hash>".
- Running text says **"Armenian Pavilion"** (the official name stays "Pavilion of the Republic of Armenia…").
- Copy the user has flagged as undecided stays as it is until they decide. Supporter names, tiers and
  order (`src/amp/pages/landing/supporters.cljs`) are theirs to set; the press kit lists supporters too.

## Release

```bash
MISE_CLOJURE_VERSION=1.12.6.1673 MISE_JAVA_VERSION=temurin-21.0.12+8.0.LTS npm run release
npx wrangler deploy --message "Release build <hash>"
```

`release/` is what Cloudflare serves, and a Caption Genius press Sync deploys whatever is in it: never
leave an unshipped or preview build there (`git checkout -- release` after a preview upload).
Review builds: `npx wrangler versions upload --preview-alias <name>` →
`https://<name>-am-pavilion.armenianpavilion.workers.dev`.

## How the site behaves (read before changing these)

- **Page transitions and first paint** — `src/amp/ui/section_transitioner.cljs`. One page on screen at a
  time. A new page is held invisible (`.ap-stage:not([data-shown])`) at the height it had last time
  (localStorage `ap:h:<path>:<width/40>`), shown with a 0.24 s blur-fade once its content and fonts are
  in, and the footer (`.ap-foot`) fades in only once the page height has settled (`data-settled`). So the
  footer never shows over unfilled space and late font swaps happen while hidden.
- **Fonts** — `src/amp/core.cljs` waits up to 1.2 s for the fonts before the first render.
- **Scroll** — manual restoration in `src/amp/services/router.cljs`; the transitioner runs the held
  scroll (`flush-scroll!`) once the new page is in.
- **Link previews** — `cloudflare/site/worker.js` rewrites meta tags for `/blog/*`, `/films/*`, `/press*`
  (see `run_worker_first` in `wrangler.jsonc`); `build/og-posts.js` writes its posts/films JSON.
- **Living grounds** (home, The Unit chapter) — plain JS in `resources/data/grounds/`: `engine.js`
  (helpers, Life, iso), `player.js` (manifest of 20 pieces, picker, pause/next, `?ground=<id>` to lock
  one), `01-…20-*.js` (one piece each, `Grounds.register({id, create(env)})`, drawn inside
  `env.stage`, clear of `G.sheltered`). Loaded by `use-living-ground` in `pages/landing/page.cljs` only
  near the chapter. The signatures and ideas in the manifest are placeholders until the user supplies
  real ones. The chapter's colour clock is the CSS `ap-ground` animation (49 s, 7 s per pigment).
- **Press** — two sources. The image list on `/press` comes from the Caption Genius project
  "Pavilion — Press" via `scripts/press.mjs` / `press-sync.sh` (don't hand-edit
  `resources/data/press/`). The press kit text (both languages) is generated by `npm run press:kit` from
  the Markdown in Dropbox `the_studio/public_relations/press_kit/` into `src/amp/data/press_kit.cljs`:
  change the Markdown and regenerate, never the generated file.

## QA

- `npm run qa:cls` — layout-shift sweep (buffered observer, both widths).
- For first-paint problems, test throttled (latency 150 ms, 1.6 Mbps, CPU ×4) against a release build
  served with an SPA fallback (`npx serve -s release -l 5055`); the dev build is too heavy to judge.
- Check 1440 and 390, light and dark, before calling a visual change done.
